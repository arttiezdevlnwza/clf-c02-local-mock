Q05Well-Architected: Stop guessing capacityCloud Concepts · L13 — Well-Architected SolutionsUnscored

Which AWS Well-Architected Framework pillar includes the principle of stopping capacity guesses and using automatic scaling?

คำแปล: โจทย์ถามว่า Design Principle 'Stop guessing capacity' และการใช้ Automatic Scaling ถูกจัดอยู่ใน Pillar ใด

ตอบที่เลือกPerformance Efficiency

เฉลยReliability

ตามกรอบการจัดหมวดในข้อสอบนี้ 'Stop guessing capacity' เป็น Design Principle ของ Reliability แม้การเลือกขนาดทรัพยากรให้เหมาะกับงานจะเกี่ยวข้องกับ Performance Efficiency

Cost Optimizationมุ่งลด Waste และเพิ่มความคุ้มค่าด้านต้นทุน ไม่ใช่ชื่อ Pillar ของหลักการที่ถาม
Performance Efficiencyมุ่งเลือกทรัพยากร/ปรับ Performance ให้เหมาะ แต่ 'Stop guessing capacity' เป็นคำเฉพาะของ Reliability
Operational Excellenceเน้นกระบวนการ Operate/Improve Workloads เช่น Runbooks และ Change Management
Reliabilityเน้นระบบรับ Capacity/Demand ได้ตามต้องการและฟื้นตัวจากความล้มเหลว

จำให้แม่น: Stop guessing capacity → Reliability | Select suitable resources for latency/throughput → Performance Efficiency

Q09Provider vs Customer ComplianceSecurity and Compliance · L10 — Monitoring, Compliance, and GovernanceScored

AWS has a compliance report for a service. Does that automatically certify a customer application using the service?

คำแปล: รายงาน Compliance ของ AWS รับรองแอปของลูกค้าและการตั้งค่าของลูกค้าโดยอัตโนมัติหรือไม่

ตอบที่เลือกYes, including all customer configurations

เฉลยNo, the customer must also satisfy its own applicable controls

AWS มีรายงานและการรับรอง Controls ที่ AWS รับผิดชอบ แต่การใช้บริการที่มีรายงานไม่ได้ทำให้ Application หรือ Configurations ของลูกค้าได้รับการรับรองอัตโนมัติ ลูกค้าต้องรับผิดชอบ Controls ที่เกี่ยวข้องของตนเอง

No, the customer must also satisfy its own applicable controlsถูก: Provider Compliance ไม่แทน Customer Compliance
No AWS services can support regulated dataผิด: บางบริการรองรับ Regulated Workloads ได้ภายใต้เงื่อนไขที่เกี่ยวข้อง
Yes, including all customer configurationsผิด: AWS ไม่ได้เป็นผู้รับรองการตั้งค่าของลูกค้าทุกส่วน
Yes, if the application uses a free support planผิด: Support Plan ไม่ใช่ตัวกำหนดการผ่านมาตรฐาน Compliance

จำให้แม่น: AWS Compliance Report ≠ Customer Application Automatically Certified

Q24Database Migration: Rehost vs ReplatformCloud Concepts · L12 — Migrating to the AWS CloudScored

A company moves a self-managed MySQL database on a VM to Amazon RDS for MySQL to reduce patching, backup, and failover work without changing the application schema or queries. Which migration strategy is this?

คำแปล: ย้าย MySQL ที่ดูแลเองบน VM ไป Amazon RDS for MySQL เพื่อให้ AWS ช่วยดูแล Patch/Backup/Failover โดยไม่เปลี่ยน Schema หรือ Query

ตอบที่เลือกRehost

เฉลยReplatform

แม้ Application SQL ไม่เปลี่ยน แต่มีการเปลี่ยนจาก Self-managed Database ไปเป็น Managed Database Platform จึงเป็น Replatform ไม่ใช่ Rehost ที่ย้าย VM/Workload แบบแทบไม่เปลี่ยนวิธี Host

RehostLift-and-shift VM/Application แบบ As-is เช่น VM → EC2 โดยไม่เปลี่ยน Database Platform
Refactorปรับ Code/Architecture มากเพื่อใช้ Cloud-native Patterns
Repurchaseยกเลิกโซลูชันเดิมแล้วซื้อ SaaS/Commercial Product ทดแทน
Replatformย้าย Workload พร้อมปรับ Platform บางส่วน เช่น Self-managed DB → RDS

จำให้แม่น: VM → EC2 (แทบไม่เปลี่ยน) = Rehost | VM MySQL → RDS = Replatform | ระบบเดิม → SaaS ใหม่ = Repurchase

Q36Subnet belongs to a single AZCloud Technology and Services · L04 — Going Global / L05 — NetworkingScored

Which statement correctly describes a VPC subnet?

คำแปล: Subnet ใน Amazon VPC มีความสัมพันธ์กับ Availability Zone อย่างไร

ตอบที่เลือกIt automatically duplicates every instance into all AZs

เฉลยIt resides in one Availability Zone

VPC ครอบคลุม Region แต่ Subnet แต่ละแห่งต้องถูกสร้างใน AZ เดียว การสร้าง Subnet ไม่ได้ทำให้ EC2 Instances ถูก Duplicate ข้าม AZ โดยอัตโนมัติ ต้องออกแบบการกระจาย/Replication แยกเอง

It spans all Regionsผิด: VPC อยู่ภายใน Region ไม่ใช่ครอบคลุมทุก Region
It resides in one Availability Zoneถูก: Subnet หนึ่งอยู่ใน AZ หนึ่งแห่งเท่านั้น
It is an edge locationผิด: Edge Location เป็นโครงสร้าง CDN/Edge ไม่ใช่ VPC Subnet
It automatically duplicates every instance into all AZsผิด: Subnet ไม่ได้ Replicate EC2 ข้าม AZ ให้อัตโนมัติ

จำให้แม่น: 1 VPC = 1 Region | 1 Region = multiple AZs | 1 Subnet = 1 AZ

Q38Consolidated Billing vs IAM Account BoundaryBilling, Pricing, and Support · L11 — Pricing and SupportScored

Which TWO statements about consolidated billing are correct? (Select TWO.)

คำแปล: เลือกสองข้อความที่ถูกเกี่ยวกับการรวมการเรียกเก็บเงินหลาย AWS Accounts

ตอบที่เลือกEligible usage can be combined for volume pricing + Consolidated billing removes IAM account boundaries

เฉลยEligible usage can be combined for volume pricing + Eligible RI and Savings Plans benefits can be shared subject to sharing settings

Consolidated Billing ช่วยรวม Usage ตามเงื่อนไขเพื่อคำนวณ Volume Pricing และแชร์ RI/Savings Plans Discounts ที่เข้าเงื่อนไขตาม Sharing Settings แต่ไม่ได้รวม Security/IAM Boundaries ของ Member Accounts

Eligible usage can be combined for volume pricingถูก: Usage ที่เข้าเกณฑ์สามารถรวมเพื่อรับ Volume Pricing Benefit
Consolidated billing removes IAM account boundariesผิด: AWS Accounts ยังมี IAM/Root Credentials และ Security Boundaries แยกกัน
An RI purchase always launches a new server in every accountผิด: Reserved Instance เป็น Billing Benefit ไม่ใช่การ Launch Servers อัตโนมัติ
All member accounts share root credentialsผิด: Root Credentials แยกตาม AWS Account
Eligible RI and Savings Plans benefits can be shared subject to sharing settingsถูก: Sharing Discounts ทำได้ตาม Eligibility และ Sharing Settings

จำให้แม่น: Consolidated Billing = one bill / eligible discounts; NOT shared IAM or root credentials

Q43Savings Plans Commitment UtilizationBilling, Pricing, and Support · L11 — Pricing and SupportScored

A team buys a Savings Plan for peak usage that occurs only briefly each month. What is the main cost risk?

คำแปล: ซื้อ Savings Plan อ้างอิง Peak ที่เกิดแค่ช่วงสั้น ๆ ของเดือน มีความเสี่ยงด้านต้นทุนอะไร

ตอบที่เลือกSavings Plans automatically lower the commitment each hour

เฉลยThe hourly commitment may be underused outside the peak

Savings Plans ผูก Commitment ด้านยอดใช้ Compute ต่อชั่วโมงสำหรับระยะสัญญา ไม่ลด Commitment ลงเองเมื่อ Workload ลดลง ดังนั้นการซื้อเผื่อ Peak สั้น ๆ อาจเหลือ Unused Commitment ในชั่วโมงส่วนใหญ่

The hourly commitment may be underused outside the peakถูก: Commit สูงเกิน Baseline Usage ทำให้จ่ายเกินส่วนที่คุ้มค่า
Savings Plans automatically lower the commitment each hourผิด: Commitment ไม่ลดตาม Demand โดยอัตโนมัติ
All unused commitment is always refundedผิด: ไม่สามารถถือว่า Unused Commitment จะได้รับเงินคืนเสมอ
Savings Plans guarantee capacity for the peakผิด: Savings Plans เป็น Pricing Discount ไม่ใช่ Capacity Reservation

จำให้แม่น: Savings Plans = fixed hourly spend commitment, not auto-scaling commitment or capacity guarantee

Q55AWS Cloud Adoption Framework PerspectivesCloud Concepts · L12 — Migrating to the AWS CloudUnscored

During cloud adoption planning, an organization needs policies for budget allocation, risk control, and resource use aligned with internal regulations. Which AWS Cloud Adoption Framework perspective applies?

คำแปล: องค์กรต้องกำหนด Policy ด้าน Budget, Risk และ Resource Use ให้เป็นไปตามกฎภายใน ระหว่างวางแผน Cloud Adoption

ตอบที่เลือกBusiness Perspective

เฉลยGovernance Perspective

โจทย์เน้นกรอบควบคุม/นโยบายองค์กร เช่น Budget Allocation, Risk Management และ Internal Regulations ซึ่งเป็น Governance Perspective ส่วน Business Perspective เน้นคุณค่าธุรกิจ/ผลลัพธ์และการลงทุน

Governance Perspectiveถูก: กำหนด/กำกับ Policies, Risk และ Cloud Governance
People Perspectiveเน้นบุคลากร ทักษะ และการเปลี่ยนผ่านองค์กร
Platform Perspectiveเน้นโครงสร้าง/สถาปัตยกรรมแพลตฟอร์ม Cloud
Business Perspectiveผิด: เน้น Business Outcomes, Value และการจัดลำดับ Investments ไม่ใช่การกำกับ Policies เป็นหลัก

จำให้แม่น: Policies + risk + compliance controls → Governance | Business outcomes + value → Business

Q59Penetration Testing PolicySecurity and Compliance · L09 — SecurityUnscored

Before penetration testing an AWS workload, what should a customer check?

คำแปล: ก่อนทำ Penetration Testing บน AWS ลูกค้าต้องตรวจสอบอะไร

ตอบที่เลือกWhether all AWS services are always permitted targets

เฉลยThe current AWS testing policy and permitted services and conditions

ต้องอ่านนโยบาย Penetration Testing ปัจจุบันของ AWS ว่าบริการ/รูปแบบการทดสอบใดอนุญาตและมีข้อจำกัดอย่างไร ไม่ควรคิดว่าทุก AWS Service สามารถทดสอบได้โดยไม่ต้องดูเงื่อนไข

The current AWS testing policy and permitted services and conditionsถูก: ตรวจ Policy/Scope และเงื่อนไขก่อนทดสอบ
Whether all AWS services are always permitted targetsผิด: ไม่สามารถสรุปว่าบริการทุกตัวเปิดให้ทดสอบได้ทุกรูปแบบ
Whether the support plan automatically authorizes attacksผิด: Support Plan ไม่ใช่การอนุญาต Pentest ทุกประเภท
Only the number of AWS accounts in the organizationผิด: จำนวน Accounts ไม่ใช่เกณฑ์อนุญาต Penetration Testing

จำให้แม่น: Penetration test → read current AWS permitted services and testing rules

Q60AMI vs CloudFormationCloud Technology and Services · L02 — Compute in the Cloud / L03 — Compute ServicesScored

A company needs to launch many EC2 instances with identical operating systems, software, and configuration without reinstalling software manually. What should it use as the template?

คำแปล: ต้องเปิด EC2 จำนวนมากที่มี OS, Software และ Configuration เหมือนกันโดยไม่ติดตั้งใหม่ทีละเครื่อง

ตอบที่เลือกAWS CloudFormation template only

เฉลยAmazon Machine Image (AMI)

AMI เป็น Image Template ของ EC2 ที่มี OS และ Software/Config ตามที่สร้างไว้สำหรับ Launch Instance ซ้ำ ๆ ส่วน CloudFormation เป็น Infrastructure-as-Code Template ที่สร้าง Resources และสามารถอ้างอิง AMI ได้ แต่ไม่ใช่ตัวเก็บ OS/Software Image โดยตรง

AWS Systems Managerช่วย Automate/Manage Instances แต่ไม่ใช่ EC2 Boot Image Template ในโจทย์
Amazon Machine Image (AMI)ถูก: Template ของ EC2 Instance ที่มี OS/Software/Configuration
Amazon EBS snapshot onlySnapshot เป็น Backup/ต้นทาง Volume แต่ไม่ใช่คำตอบตรงสำหรับ Instance Launch Template ทั้งชุด
AWS CloudFormation template onlyผิด: สร้าง Infrastructure Resources จาก Template แต่ไม่ได้แทน AMI ที่บรรจุ OS และ Software

จำให้แม่น: Identical preconfigured EC2 OS/Software → AMI | Define Infrastructure Resources → CloudFormation
